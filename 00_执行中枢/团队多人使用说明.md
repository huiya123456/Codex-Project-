# 团队多人使用说明

本项目应作为“团队共享仓库 + 每人本地使用”的工作台使用。不要依赖某一台电脑上的本地目录作为唯一版本。

## 推荐协作方式

1. 由负责人把当前项目推送到公司 Git 仓库、GitHub、GitLab 或 Gitee。
2. 每个成员在自己的电脑 clone 同一个仓库。
3. 每个成员用 Codex 打开自己电脑上的项目目录。
4. 公共配置、模板、Demo、评分表和数字资产通过 Git 同步。
5. 原始训练数据如含客户信息或内部敏感内容，先脱敏，再提交；不能脱敏的只提交蒸馏总结。

## 成员分工建议

| 角色 | 主要目录 | 职责 |
|---|---|---|
| 负责人 | `00_执行中枢`、`03_数字资产库`、`05_蒸馏SOP` | 总控、评分、合并、蒸馏版本管理 |
| 成员A | `02_训练数据/T-A_成员A_Slot策划方向` | Slot 策划训练数据沉淀 |
| 成员B | `02_训练数据/T-B_成员B_文审机策划方向` | 文审机策划训练数据沉淀 |
| 成员C | `02_训练数据/T-C_成员C_策划执行层通用` | 策划执行层训练数据沉淀 |
| 成员D | `04_Demo基准测试`、`03_数字资产库` | Demo、测试、代码模块或美术资产沉淀 |

## 每台电脑的首次设置

```powershell
git clone <远程仓库地址>
cd <项目目录>
git status
```

然后用 Codex 打开该项目目录，按 `01_智能体配置/00_批量配置索引.md` 配置岗位智能体。

## 路径原则

- 文档中只记录相对路径，例如 `01_智能体配置/03_Slot策划智能体.md`。
- 每个成员本地项目放在哪里都可以，例如 `<任意本地目录>\Project`。
- 不要在公共文档中写死某个人电脑上的 `E:\`、`H:\`、`C:\Users\...` 路径。
- 如需使用 worktree，每个成员可在自己电脑上建立本地 worktree 根目录，例如 `<项目同级目录>\Project_Worktrees`。

## 日常提交规则

1. 每天开始前先 `git pull`。
2. 每个成员只改自己负责的目录，减少冲突。
3. 训练数据先脱敏再提交。
4. Demo V0 永远不覆盖，新对比版本新建 `Demo_V1`、`Demo_V2`。
5. 蒸馏记录必须写入 `05_蒸馏SOP/蒸馏记录表.md`。

## 负责人每周检查

- 检查 Demo 评分表是否填写。
- 检查训练数据是否按成员归档。
- 检查新增资产是否进入 `03_数字资产库` 并标记质量评级。
- 检查是否存在写死本机路径的新文件。
- 检查未提交文件，避免成果只留在个人电脑。
